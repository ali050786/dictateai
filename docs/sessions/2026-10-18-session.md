# DictateAI — build session, 2026-10-18

A record of one long working session with Claude (Opus 5.5) that took DictateAI from a dev-only prototype to an installed Mac app: local AI cleanup, a security and state pass, and a DMG installer. Product decisions were made with the BMAD party-mode crew (Mary, analyst · John, PM · Sally, UX · Winston, architect · Amelia, engineer).

**Start:** commit `4f00b60` (pill position, sleeker pill, mute while speaking), never pushed.
**End:** `main` at `3bcc5ca`, three PRs merged, DictateAI installed in /Applications and dictating.

---

## 1. Who it's for

Mac users who hit **Wispr Flow's free cap** (2,000 words a week on desktop) and are stuck until it resets. Wispr's cap message reads "Weekly dictation limit reached… Upgrade for unlimited access", with one button: Upgrade.

**DictateAI's promise:** dictation on your Mac that never runs out. Speech-to-text (WhisperKit) and text cleanup (Qwen on MLX) both run locally, so there is no cap and nothing leaves the Mac. Cloud cleanup is an opt-in with the user's own OpenRouter key.

## 3. Decisions (and why)

Full record: `sentry/_bmad-output/planning-artifacts/dictateai-llm-cleanup-decisions.md`.

- **Local is the product, cloud is optional.** A cap is the problem we solve; only local has none.
- **Model by language, picked automatically.** 3B is fast and right for English; 7B is the smallest Qwen that kept Hindi in Devanagari (3B translated it).
- **Dropped:** Qwen 1.5B (not reliable enough), 0.5B, a "1.1B" (no such Qwen), the Fast/Balanced/Best labels, and `openrouter/free` (slow, random model, 50 requests a day).
- **The picker hides behind "Advanced".** Wispr users never pick a model; the app decides and explains once.
- **Cloud → local can happen quietly; local → cloud never without asking.** The user's words don't leave the Mac unless they chose that.
- **Messages are calm notifications, not pill text.** The pill (240×52) can't fit a sentence and must keep showing dictation state.

## 4. Final pass: state, security, UX

Ranked by harm to the user (John's rule), all nine built and tested:

1. **Clipboard:** paste saves and restores every clipboard item and type (images, rich text, files), unless the user copied something new meanwhile. Our text is marked transient so clipboard managers skip it.
2. **Key encryption:** the OpenRouter key is stored with Electron `safeStorage` (Keychain); a plaintext key is migrated on startup.
3. **Local model server:** `--allowed-origins` set to an origin that can't match, so web pages can't read the model's replies.
4. **Logs:** dictated text and field contents are logged as their length only; `DICTATEAI_DEBUG=1` logs the text.
5. **Mute switch:** stopped toggling several times after settings reloads (its listener was being re-attached).
6. **History:** persists across restarts (`~/.dictateai/history.json`), with a Clear button. The hub and tray show your real shortcut.
7. **Hardening:** Content-Security-Policy on both pages, no-`eval` dev source maps, windows can't navigate or open new windows, and `openExternal` only opens `https://openrouter.ai`.
8. **Single instance:** a second launch opens the existing hub instead of fighting over the hotkey and ports.
9. **State:** `main.ts` keeps dictation state in one `dictation` object with a session number, and settings moved to `src/config.ts`. Fixed along the way: a new recording's audio could be wiped by the previous dictation finishing, and empty recordings left the pill stuck on "Transcribing".

Data in `~/.dictateai` is owner-only (folder 0700, files 0600).

## 5. Bugs found and fixed

| Symptom | Cause | Fix |
|---|---|---|
| Packaged app couldn't type or use the hotkey | Native addon loaded from a project path | Ship as extra resource, load from `process.resourcesPath` |
| Cursor jumped to the start after dictation | Whole field value rewritten | Insert at cursor; wait for Chromium; else paste |
| Dictionary changed "We" to "Hi," (and more) | Learned from the whole field, from its first word | Align to the dictated stretch; single-word fixes; two-fix threshold |
| Slow fallback after a cloud 429 | OpenAI SDK retried twice | `maxRetries: 0` |
| "Ready" reported when another server held the port | Health check answered by the other server | Reuse an existing server; ready only after warm-up succeeds |
| Pasting wiped a copied image | Only plain text was saved/restored | Snapshot and restore all clipboard items |
| New recording's audio lost when talking again quickly | Old dictation cleared the shared buffer | Session-scoped state; process in order |
| Pill stuck on "Transcribing" | Empty/short recordings never hid it | Hide after skip |
| Installed app: WhisperKit "permission denied" | Models in `~/Documents` (protected per app) | Models in `~/.dictateai/whisperkit` |
| Installed app: push-to-talk dead until restart | No Accessibility at launch | Poll a non-prompting check, start when granted |
| Restarting push-to-talk could crash | Assigning over a joinable `std::thread` | Join the failed thread first |
| Installed app: "No speech detected" always | macOS never asked for the microphone; silence fed | `askForMediaAccess` at launch; "Microphone blocked" message; proper signing |

## 6. How to install and update

See `README.md`. In short:

```bash
npm install && npm run make
```

Open `out/make/dmg/arm64/DictateAI-0.1.0-arm64.dmg`, drag DictateAI into Applications, open it, and allow Accessibility and Microphone. Requires `brew install whisperkit-cli` and `uv tool install mlx-lm`. After each rebuild, macOS may ask for Accessibility again (the app is ad-hoc signed, not notarized).

## 7. Known limits and next steps

- `mlx_lm.server` has no authentication: a web page can't read replies, but could still send a blind request that makes the Mac generate.
- The dev app and the installed app have different Keychain identities: a key saved in one must be re-entered in the other.
- Untested: cloud cleanup with the encrypted key; Qwen 14B; the cursor fix in apps other than Claude.
- Not notarized: sharing builds with others needs an Apple Developer ID and notarization.
- `npm run lint` reports formatting issues in files that predate this session.
- Ideas raised but not built: skip cleanup for very short phrases; a 20-dictation test set to compare models.
